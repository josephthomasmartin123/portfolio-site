# Portfolio Site — Claude Code Guide

## Stack
Plain HTML/CSS/vanilla JS. No frameworks, no build tools, no npm.

## File structure
```
portfolio-site/
├── index.html          # Homepage (shows all projects)
├── projects.html       # Projects listing
├── about.html          # About page
├── style.css           # Single stylesheet — all styles live here
├── lightbox.js         # Lightbox for project page images
└── assets/
    └── projects/
        └── <Project Name>/   # One folder per project
            ├── <page>.html   # Project detail page
            └── <images>
```

## Path conventions — CRITICAL

Project pages are three levels deep from root (`assets/projects/<name>/`). Always use `../../../` to reach root-level files:

```html
<link rel="stylesheet" href="../../../style.css" />
<script src="../../../lightbox.js"></script>
<a href="../../../index.html">Joseph Martin</a>
<a href="../../../projects.html">Projects</a>
```

Using `../../` is a **common bug** — it resolves to `assets/style.css` which doesn't exist. VS Code Live Server returns index.html for 404s, which browsers reject as a stylesheet (wrong MIME type), making pages render as raw text.

## Images

- HEIC images must be converted to JPEG before use:
  `sips -s format jpeg "$f" --out "${f%.HEIC}.jpg"`
- Use URL-encoded paths in HTML: spaces → `%20`
- Gallery images: use `<img class="gallery-img" ...>` (lightbox picks these up via lightbox.js)

## Agents & skills

This project is set up to be agent-friendly. Anything in `.claude/` is meant to be discovered and invoked automatically — by Claude Code (slash commands) or Cowork (skill paths).

### Skills — `.claude/skills/`

| Skill | What it does | Invoke it when |
|---|---|---|
| `new-project` | Scaffolds a new project — folder, page from template, photos, dropdown updates across all pages | "add a new project", "scaffold X" |
| `write-project` | Drafts/polishes the prose body of a project page in Joe's voice (reads two existing pages first to calibrate) | "write up the X project", "polish this draft" |
| `audit-site` | Read-only consistency sweep: `../../../` paths, dropdown drift, broken images, leftover HEIC, footer/lightbox completeness | "audit the site", "anything broken?" |
| `sync-claude-md` | Regenerates the AUTO-SYNC blocks in this file from real site state. Hand-maintained sections are preserved | "sync claude.md", or after `new-project` |

Each skill lives at `.claude/skills/<name>/SKILL.md` with a YAML frontmatter (`name`, `description`) and prose instructions. Templates and helper files sit alongside the SKILL.md.

### Slash commands — `.claude/commands/`

In Claude Code, the same skills are available as slash commands:

- `/new-project [name]` — scaffold a new project
- `/write-project [project]` — draft/polish a writeup
- `/audit-site` — run the consistency sweep
- `/sync-claude-md` — refresh this file

Each command is a thin wrapper that reads the corresponding `SKILL.md` and forwards arguments via `$ARGUMENTS`.

### Cowork

In Cowork, invoke a skill by reading its `SKILL.md` directly:

> "Use the new-project skill at `.claude/skills/new-project/SKILL.md` to add a project called Vacuum Tube Amp"

The agent reads the file and follows its instructions. Same workflow, different invocation.

### Auto-sync markers

Two regions of this file are regenerated by `sync-claude-md` and bounded by HTML comments:

- `<!-- AUTO-SYNC: dropdown -->` ... `<!-- /AUTO-SYNC -->` (the `<ul class="dropdown-menu">` snippet)
- `<!-- AUTO-SYNC: project-table -->` ... `<!-- /AUTO-SYNC -->` (the Existing projects table)

Don't edit content inside the markers by hand — it'll be overwritten. Edit `index.html`'s dropdown (the canonical source) and run `/sync-claude-md`.

### Adding a new skill

1. Create `.claude/skills/<name>/SKILL.md` with YAML frontmatter (`name`, `description` — make the description specific so the agent picks it up automatically).
2. (Optional) Add a thin slash-command wrapper at `.claude/commands/<name>.md`.
3. Reference it from this section so it's discoverable.
